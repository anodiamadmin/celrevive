## Setup Checklist

1. Open PowerShell in `celrevive_backend`:

```powershell
cd C:\Personal\celrevive\celrevive_backend
```

2. Create and activate a virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

3. Install dependencies:

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

4. Create `.env` from `.env.example` and configure:

```env
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/celrevive
GEMINI_API_KEY=your-key-here
VISUAL_AI_MODEL=gemini-2.5-pro
SKIN_IMAGE_STORAGE_ROOT=./data/skin_images
```

5. Start PostgreSQL and create the `celrevive` database.

6. Run the attached DDL:

```powershell
psql -U postgres -d celrevive -f ..\architecture\database\CelRevive_DDL_updated.sql
```

7. Load the reference data, especially `skin_concern` rows:

```powershell
psql -U postgres -d celrevive -f ..\architecture\database\CelRevive_DML_Primary_Insert_updated.sql
```

8. Create at least one `customer_session` row with status `STARTED` and consent enabled. The upload route currently requires its UUID as the multipart `session_id` field.

9. Start the backend:

```powershell
uvicorn app.main:app --reload
```

10. Test the endpoint using the session UUID:

```powershell
curl.exe -X POST "http://127.0.0.1:8000/api/v1/image-validation" `
  -F "session_id=YOUR_SESSION_UUID" `
  -F "image=@C:\path\to\valid-image.jpg"
```

11. Confirm a successful response contains:

```json
{
  "valid": true,
  "image_id": "...",
  "next_step": "questionnaire"
}
```

12. Verify:
- The image exists under `data/skin_images`.
- `skin_image` contains the metadata row.
- `customer_session.session_status` becomes `IMAGE_RECEIVED`.
- The background task sends the image to Gemini.
- `session_skin_concern_detection` receives all 28 concern rows.

13. Run tests after installation:

```powershell
python -m pytest -q
```

The questionnaire template is currently only a corrected JSON artifact. Questionnaire processing is not part of the implemented 1.1–2.5 image-analysis flow.

### Still required before the system runs

1. Install dependencies from `requirements.txt`.

2. Configure `.env` with:
   - `DATABASE_URL`
   - `GEMINI_API_KEY`
   - `VISUAL_AI_MODEL`
   - `SKIN_IMAGE_STORAGE_ROOT`

3. Create the PostgreSQL database.

4. Run the DDL and primary seed data.

5. Create a valid `customer_session` before uploading an image.

6. Test the multipart request with:
   - `image`
   - `session_id`

7. Confirm PostgreSQL contains the required `skin_concern` reference rows. Detection persistence will fail if those rows are missing.

8. Run and repair the full test suite. The existing API tests still assume image validation can run without a `session_id`; they need to be updated for the new intake contract.

9. Add integration tests for:
   - successful image storage
   - session status update
   - commit-before-background-task ordering
   - missing session handling
   - image/session mismatch
   - Visual AI persistence
   - retry idempotency
   - background-task failures

10. Decide whether the questionnaire template should later be copied into the backend package. It is currently valid JSON, but questionnaire processing is outside 1.1–2.5 and is not wired into the image-analysis flow.

The main remaining work is environment/database setup and integration-test completion, rather than another major application redesign.
